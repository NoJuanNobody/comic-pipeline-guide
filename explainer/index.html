What is comic-pipeline-guide and what is it like to use?

Long image

A

Answer

It is a written guide, not software: one web page, a PDF and three diagrams. It shows a person or an AI agent how to build a code-driven comic pipeline, phase by phase.

  1. You read a field report of one build, where scripts became lettering and panels became layers for print and motion.1
  2. You get a 14-phase playbook (Phase 0 to 13), each phase with a goal, a spec, a "done when" test and a likely failure.2
  3. You get 32 interview questions and a brief you can paste into your own agent's first message.3
  4. The guide says plainly that no real panel art has gone through the pipeline it describes.4

Applies toThis repository holds the guide only: index.html, guide.pdf, diagrams/ and build.mjs. The pipeline code the guide describes is not in this repo.

What path does a reader take through the guide?

Diagram structure
  • Check status table status
  • Learn the three tracks idea
  • Interview the artist interview
  • Paste the agent brief brief
  • Run phases 1 to 13 phases
  • Tick acceptance checklist checklist
  • brief → phases
  • idea → interview
  • interview → brief · decision table
  • phases → checklist · done when
  • status → idea
  1. Check status table ↗

    Start with "What is real and what isn't". It marks each piece as built and verified, lightly tested, or never run.

  2. Learn the three tracks ↗

    "The idea" and "How it works" explain the art, text and motion tracks and the files they share.

  3. Interview the artist ↗

    Phase 0 asks the artist 32 questions and labels every answer DECIDED, WORKING ASSUMPTION or OPEN.

  4. Paste the agent brief ↗

    The appendix has a ready brief to paste into your agent's first message, together with the guide.

  5. Run phases 1 to 13 ↗

    Each phase ends with a "done when" test. Do not start the next phase until it passes.

  6. Tick acceptance checklist ↗

    The appendix checklist has ten checks, from the decision table to a printed proof.

What goes in, and what comes out?

ItemWhat it is
You bringAn artist's scripts (the guide's example parses Fountain), hand-inked art, and an AI agent with shell access
The guide gives youPhase specs with code snippets, lint rules, ffmpeg commands, JSON shapes and a file map
Your agent buildsA renderer, a lettering manifest, an art ingest step, a colour lab, a layout push, a test font and a pilot-page kit
The pipeline then producesLettered print pages and motion pieces, both fed from the same layers and the same script text

The guide connects the three tracks through three files: panel.json with layer PNGs, lettering/issue-NN.json, and beats.json.5

Formats
Web page (index.html), guide.pdf, three diagram pages in diagrams/
Audience
Humans and AI agents; the playbook is written for an agent with shell access that can run sub-agents
Example stack
Node, Playwright, ffmpeg, Python with librosa, and the ArtCraft apps (DesignCraft, PhotoCraft)

How do you rebuild the page?

The README says node build.mjs writes index.html.6 The script reads its Markdown from ../article/building-a-comic-pipeline-with-ai.md, a folder outside this repository.7 A fresh clone cannot rebuild the page; edit the published index.html or supply that article file.
